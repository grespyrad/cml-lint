# Форматирование CML и pre-commit

## Установка

Нужен Go 1.27.1. Java для работы `cm` не нужна.

```sh
go install github.com/grespyrad/cml-lint/cmd/cm@latest
cm --version
```

Либо соберите из checkout:

```sh
go build -o bin/cm ./cmd/cm
bin/cm format model.cml
```

Если `cm` не найден, добавьте каталог `$(go env GOPATH)/bin` в PATH либо используйте
абсолютный путь к бинарнику. Для воспроизводимой установки замените `@latest`
конкретным опубликованным tag или commit с нужной версией форматтера.

## Повседневное использование

```sh
# Посмотреть результат в stdout, исходник не меняется.
cm format model.cml

# Исправить один или несколько файлов, в том числе с пробелами в имени.
cm format -w model.cml 'models/service model.cml'

# Рекурсивно отформатировать каталоги.
cm format -w models/ contracts/

# Только проверить весь каталог; удобно для CI и ручной проверки.
cm format --check models/

# Отформатировать файл, затем проверить его семантику и импорты.
cm lint --fix -i model.cml
cm lint --json -i model.cml

# Строгий исходный CML либо собственный словарь keywords.
cm --original format -w models/
cm --keywords keywords.json format -w models/

# Имена файлов, начинающиеся с дефиса, передаются после --.
cm format -w -- '-model.cml'
```

Flags ставятся перед путями. `-i`/`--input` остаётся совместимым способом передать
один файл. Несколько файлов и каталоги поддерживаются в `format -w` и
`format --check`; stdout и `lint` принимают один файл. В stdout идёт только CML,
ошибки пишутся в stderr; успешный `-w` ничего не печатает.

Каталоги обходятся рекурсивно, обрабатываются только имена с суффиксом `.cml`.
Вложенные `.git`, `vendor`, `node_modules` и symlinks пропускаются. Явно переданный
путь к обычному файлу в таком каталоге обрабатывается. `.gitignore` не используется:
для ручного обхода указывайте нужные каталоги; для файлов Git используйте pre-commit.
Повторные пути обрабатываются один раз. Пустой каталог — успешный запуск без изменений.

Каждый файл записывается атомарно с сохранением прав. Ошибка синтаксиса оставляет
этот файл неизменённым. Остальные файлы в пакете продолжают обрабатываться;
общей транзакции на все файлы нет. `format` проверяет синтаксис; семантические
ошибки проверяются отдельной командой `lint` или `validate`.

Коды завершения: `0` — успех; `1` — ошибка чтения, записи, синтаксиса или
расхождение при `--check`; `2` — несовместимые или недостающие аргументы.

## Стиль

Форматирование применяется автоматически через `format -w` и `lint --fix`.
Дополнительный `--pretty` не нужен. Стиль един для всех проектов:

- два пробела на уровень; открывающая `{` на строке заголовка;
- каждое свойство, поле и операция с новой строки;
- одна пустая строка между самостоятельными объявлениями и отношениями;
- без пустых строк на краях блока, включая пустой блок;
- generic types и ссылки компактны: `List<@Request>`, `Service::operation`;
- пробелы вокруг `=`, стрелок и после запятых; роли — `[U, OHS, PL]`;
- мягкий лимит 100 Unicode code points: длинные параметры, списки и flow clauses
  переносятся с дополнительным отступом; длинный одиночный токен не разрезается;
  параметры с комментариями всегда раскрываются на несколько строк;
- непустой файл завершается одним LF; строки, escapes, aliases и комментарии
  сохраняются дословно. Внутренний whitespace многострочного литерала не меняется.

Например:

```cml
BoundedContext ServiceIntegration {
  domainVisionStatement = "Request processing"

  Aggregate Requests {
    Entity Request {
      aggregateRoot
      String id
      - List<@Policy> policies
    }

    ValueObject Policy {
      String code
    }
  }
}
```

После обновления старые файлы могут потребовать однократного `cm format -w models/`.
[Образец из оригинального Java formatter](../testdata/format-reference/README.md)
содержит сравнение и команду воспроизведения. JVM требуется только для этого исследования.

## Автоматический pre-commit

Рекомендуемый способ — [pre-commit framework](https://pre-commit.com/). Он передаёт
изменённые staged файлы отдельными аргументами и временно убирает unstaged-изменения
при частичном индексировании. Не добавляйте `git add` внутрь hook.

Установите framework доступным в вашем окружении способом, например:

```sh
pipx install pre-commit
```

Добавьте в `.pre-commit-config.yaml` своего проекта:

```yaml
repos:
  - repo: https://github.com/grespyrad/cml-lint
    rev: main
    hooks:
      - id: cml-format
        language_version: system
```

Замените `rev: main` точным commit или tag, содержащим эту версию hook, и
закоммитьте конфигурацию. `main` показан для первого подключения; в общей
конфигурации нужен закреплённый revision. `language_version: system` использует
установленный Go 1.27.1; pre-commit сам соберёт `cm` в изолированной среде.
При обновлении закреплённого revision команда `pre-commit autoupdate` помогает
обновить конфигурацию; пересмотрите diff и результат форматирования.

```sh
# Установить Git hook в текущем проекте.
pre-commit install

# Один раз привести все отслеживаемые CML-файлы к новому стилю.
pre-commit run cml-format --all-files

# Просмотреть результат и добавить нужные изменения.
git diff
git add models/

# Обычная работа: форматирование выполнится при commit.
git commit
```

Если hook исправил файлы, pre-commit останавливает commit, чтобы можно было
просмотреть diff. Добавьте исправленные части через `git add` или `git add -p`
и повторите commit. Даже если `cm format -w` вернул `0`, framework замечает изменение
файлов. При конфликте восстановления unstaged-правок pre-commit отменяет автоисправления
hook и сохраняет исходные изменения; разрешите ситуацию вручную и повторите запуск.

Удалённые файлы и symlinks не передаются hook; имена с пробелами и дефисами
поддерживаются. `format` не требует наличия всех импортированных моделей.
Если в одном файле ошибка синтаксиса, hook сообщит её, сохранив этот файл.

Для режима без записи замените hook на `id: cml-format-check`. Для проверки в CI:

```sh
pre-commit run cml-format-check --all-files
```

Команда предполагает, что этот hook добавлен в конфигурацию. Без framework:

```sh
cm format --check models/
```

### Если cm уже установлен

Чтобы использовать свой бинарник или словарь, подключите локальный hook:

```yaml
repos:
  - repo: local
    hooks:
      - id: cml-format
        name: Форматирование CML
        language: system
        entry: cm format -w --
        types: [file]
        files: '\.cml$'
```

Для aliases замените `entry` на `cm --keywords keywords.json format -w --`.
Для исходного CML используйте `cm --original format -w --`. `keywords.json`
задаётся относительно корня проекта. Пути framework добавляет после `--`;
не вписывайте `.` или `models/` в entry — hook должен обрабатывать именно
переданные staged файлы. Конфигурация проверяется командой
`pre-commit validate-config`.

### Существующие Git hooks

Если уже задан `core.hooksPath` или установлен другой менеджер hooks, сохраните
его штатный порядок установки и добавьте вызов `pre-commit run` в существующий
`pre-commit` hook. Его ненулевой код должен останавливать commit. Не используйте
`cm format -w . && git add .`: это может добавить в коммит unstaged-изменения.

Для этого репозитория `task hooks` включает проверки разработки Go из `.githooks`.
Это отдельный механизм; `.pre-commit-hooks.yaml` предназначен для подключения
форматтера в проекты, где хранятся ваши CML-модели.

## Проверки разработчика форматтера

```sh
go test ./internal/format ./cmd/cm
go tool -modfile=tools/task.mod task fuzz
go tool -modfile=tools/task.mod task check

# Дополнительная end-to-end проверка; нужен установленный pre-commit.
go tool -modfile=tools/task.mod task hooks:verify
```

Последняя команда создаёт временный Git-репозиторий и проверяет несколько файлов,
пути с пробелами, автоисправления, повторный запуск, частичное индексирование и
отказ при синтаксической ошибке. Рабочие файлы текущего репозитория она не меняет.
