## Стиль

Два пробела на уровень; открывающая скобка на строке заголовка. Непустые и пустые
блоки раскрываются; самостоятельные объявления и отношения отделены одной пустой
строкой, поля и операции идут по одному на строке. В начале и конце блока лишних
пустых строк нет. Импорты образуют непрерывную группу. Один LF в конце непустого файла.

Пробелы вокруг = и стрелок; запятая и ; без пробела слева. Generic types, @Type,
qualified names и role brackets компактны. Лимит 100 Unicode code points мягкий:
длинные параметры и списки переносятся по запятым с дополнительными двумя пробелами.
Строки и комментарии не разрезаются и не переписываются. Комментарий после кода
остаётся с этим кодом, самостоятельные комментарии остаются перед объявлением.

## Реализация и ориентир

План переносов строится по позициям go-cml AST и токенам. Запись меняет только
whitespace; результат повторно токенизируется и парсится. Inline nodes операций,
flow и state transitions не создают ложных границ. Диалект нужен только для
распознавания keywords; исходные aliases сохраняются.

Изучены ContextMappingDSLFormatter.xtend и TacticDDDLanguageFormatter.xtend
Context Mapper v6.12.0 (eb63d120265600cc9d5f531cdbfc9ef44837d78c), запущен
настоящий IFormatter2 из опубликованного Maven CLI. Общие правила переняты как
ориентир; выбранный стиль использует spaces вместо tabs, регулярные пустые строки,
компактные generic types и перенос длинных списков. Побайтовая Java parity не цель.
JVM используется только при явном запуске reference oracle, не при обычных тестах.
